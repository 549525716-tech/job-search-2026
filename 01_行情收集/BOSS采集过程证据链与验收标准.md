# BOSS采集过程证据链与验收标准

更新时间：2026-07-02 Asia/Shanghai

## 一、本质判断

BOSS 登录安全入口只是人工登录和低频站内搜索的交接页，不是岗位采集结果。打开了多少个安全入口，都不能证明已经收集到岗位。

真正有效的采集必须留下以下至少一种证据：

1. `01_行情收集/data/raw/` 新增岗位原文文件。
2. `01_行情收集/data/jobs.jsonl` 新增带 `query`、`searchUrl`、`url`、`rawText` 或 `detailText` 的记录。
3. `01_行情收集/BOSS公开线索复核收件箱.md` 新增人工复制的岗位详情段落，并通过导入预检。
4. `01_行情收集/公开高薪销售岗位补充线索.csv` 新增带 `sourceUrl` 和 `sourceEvidence` 的岗位线索。

## 二、不能算采集完成的动作

| 动作 | 是否算采集 | 原因 |
| --- | --- | --- |
| 打开 `BOSS登录安全入口.html` | 否 | 只是本地入口页，没有岗位 DOM 和岗位正文 |
| 运行 `npm run auth:boss` | 否 | 只检查/生成安全入口，不访问 BOSS 岗位列表 |
| 运行 `npm run auth:boss -- --launch-handoff` | 否 | 只把本地入口页交给系统 Chrome 打开 |
| 生成 BOSS 搜索词清单 | 否 | 只是待搜索计划，还没有岗位详情证据 |

## 三、有效采集验收

| 验收项 | 最低要求 |
| --- | --- |
| 搜索来源 | 有平台、关键词、公司/岗位词、搜索入口或来源 URL |
| 岗位字段 | 有公司、岗位、薪资、地点、经验/学历之一、职责或要求摘要 |
| 原文证据 | 有 `rawText`、`detailText`、人工复制段落或公开页证据说明 |
| 导入结果 | 导入脚本显示可导入段落或新增岗位记录 |
| 结论权限 | 没有原文证据的内容只能标为“待复核线索”，不能写成市场结论 |

## 四、审计位置

| 证据类型 | 文件 |
| --- | --- |
| 安全入口打开/跳过日志 | `01_行情收集/data/processed/boss_action_audit.jsonl` |
| 安全入口冷却状态 | `01_行情收集/data/processed/boss_handoff_state.json` |
| BOSS 当前人工复核任务 | `01_行情收集/BOSS公开线索当前复核任务.md` |
| BOSS 人工复核收件箱 | `01_行情收集/BOSS公开线索复核收件箱.md` |
| 结构化岗位库 | `01_行情收集/data/jobs.jsonl` |
| 原始岗位文本 | `01_行情收集/data/raw/` |
| 公开高薪销售线索库 | `01_行情收集/公开高薪销售岗位补充线索.csv` |

## 五、后续工作原则

每次说“我完成了 BOSS 岗位采集”之前，必须同时给出：

1. 本次搜索关键词。
2. 新增岗位条数。
3. 新增记录所在文件。
4. 至少 3 条样例岗位的来源 URL 或原文摘录位置。
5. 哪些只是候选线索，哪些已经可进入市场结论。
