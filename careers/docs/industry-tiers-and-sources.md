# 行业分层、信息来源与执行门槛

版本：2026-09-11-v2。与[双路线发现规则](dual-route-discovery.md)共同使用；机器可读契约为 `../config/company-tier-policy.json` 和 `../config/source-catalog.json`。

**统一按“行业 → 细分赛道 → 行业内大厂/中厂/小厂/地位待核 → 公司及业务线 → 岗位”组织信息。大中小表示该赛道的市场地位，不表示人数、名气或岗位好坏。** A从行业找公司，B从岗位反查公司，两条路线最终进入同一分类体系。本次只落地规则和离线复核，不扫描、不将旧样本擅自分层、不修改历史推荐或投递。

## 一、分层标准

这是一套项目内职业研究标准，不是国家中小企业划型、权威排名或投资评级。先固定产品/客户/地域/时间的比较范围，再判断地位；不能为了称龙头临时把赛道缩到某个小地区。默认先研究中国市场，全球地位另列。同一公司在不同业务线、地域、赛道可以有不同结论。

| 展示层级 | 判断标准 | 需要的证据 |
| --- | --- | --- |
| **行业大厂（头部）** | 在该细分市场处于有依据的领先梯队；员工少也可能属于此类 | 同口径独立研究明确支持领先梯队 + 真实商业业务证据。量化份额/营收/名次用于核对市场集中度和梯队，不单凭前5定头部；只有定性梯队证据时标“定性头部”，不编名次 |
| **行业中厂（腰部）** | 已形成持续商业交付，在所选市场属于有根据的成熟挑战者或腰部群体 | 同口径比较支持腰部定位；再以多个独立付费客户、续约/连续交付或连续报告期的业务指标证明可复制经营。只找到一个项目或“没进前5”不够 |
| **行业小厂（新兴/有限覆盖）** | 有证据表明在该市场仍处于早期商业化、试点扩张或有限业务覆盖阶段 | 明确业务阶段与市场覆盖证据，并有外部比较佐证；不能以没上市、融资早、员工少或没听过直接判小厂。区域龙头应在区域口径另列，不强行降级 |
| **地位待核** | 证据缺失、不可比、过期或相互矛盾 | 保留候选和岗位，列缺什么证据；未查到资料不等于小厂，也不等于公司不好 |

**前5等名次只作头部候选信号，不是自动判定标准。** 报告必须说明研究覆盖、参与者口径、市场集中度和领先梯队依据；获奖名单、赞助榜单、少数参评企业排名不构成此依据。所有头部判定都需要独立的同口径领先梯队证据，不再增加跨行业通用的份额阈值。名次不能覆盖相反的业务阶段/市场地位证据；排名靠前但仅为长尾试点、梯队未明确或冲突未解时，当前标待核。补证后如果新兴条件成立，可再判小厂，而不是按检查顺序抢先归大厂。

### 证据和决策顺序

1. 核清实际雇主、品牌、集团、子公司与业务线；固定细分赛道和市场地域。云集团总营收不等于AI业务营收，品牌热度不等于企业服务收入。
2. 同一口径依次检查头部、腰部、新兴条件，未满足则待核。三档的已支持判断均需至少两个**独立原始发布方**，含外部市场比较和商业事实，不能两篇转载算两个来源。自述“行业第一”只能作待核线索。
3. 优先市场份额/同赛道营收/实际付费客户等可比商业指标；部署数、合同中标、案例、生态影响按证据原义解释。中标不等于回款，模型跑分不等于市场份额，定性象限不等于营收排名。
4. GPT-6负责分层及冲突判断，保存支持和反证、判定路径、理由、审查者、规则版本。Luna只收集与整理证据，不依据搜索摘要定层级。
5. 业务指标优先最近18个月；每90天检查一次分类，重大收购、业务撤销或相反证据触发提前复核。超过复核期限、只有超期指标或重大冲突未解时，当前显示待核，旧结论保留为历史。新观察时间不能给旧报告“续命”。

建议分类记录：`classification_id, employer_entity_id, business_line_id, industry_id, segment_id, geographic_market, as_of_period, tier, assessment_status, method, rationale, supporting_evidence, counterevidence, assessed_at, review_due_at, reviewer, rule_version`。企业人数/组织规模、融资阶段、现金流风险另存，未知留空；不得自动继承母公司层级。

### 采集及展示规则

- 大、中、小、待核四桶都保留。分层是整理和比较维度，不是只扫大厂的筛选器，也不是先完成行业排名才能收JD的前置门槛。
- 每轮按“赛道 × 四桶 × 路线 × 来源状态”列计划量、已尝试量、完整JD量和待续项。未发现某桶公司标“本轮未识别”，不能把其他公司硬填进去，也不能说市场不存在该类公司。
- 公司可跨赛道出现；岗位按JD服务的业务线定主归属，辅助标签可多选。原始岗位唯一ID不变，跨视图重复展示不重复计总数。
- 报告依次呈现行业分组、分层依据摘要、公司岗位列表。每岗优先显示**岗位名、固定薪核验状态、城市、管理职责、重要缺口、JD/申请链接**；公司规模不能代替薪资或稳定性判断。
- 字段未知就展示“待核/未披露”，不要整块留白；详细研究证据可折叠。旧看板尚未接入本分组，不能把本规则文件当作已更新UI。历史数据需有证据的增量分类，不覆盖原始记录。

## 二、先确定信息从哪里来

“路线A/B”是发现逻辑；“官网/招聘平台”是数据来源；“HTTP/浏览器/web工具”是读取方式，三者不能混为一谈。以下是**明确选定的来源范围和用途，不是已验证全部可抓的白名单**。

| 层次 | 选定来源 | 负责提供什么 | 本地接入边界 |
| --- | --- | --- | --- |
| 政策与产业 | 中国政府网/国务院、发改委、工信部、科技部、国家数据局；相关地方政府正式文件 | 规划、支持对象、实施条件、期限、产业方向假设 | 已有指定文档采集器；不是自动周报爬虫。入口见 `policy-sources.json`，已有受限记录优先 |
| 行业比较 | 中国信通院、相应行业协会、IDC/Gartner等原始研究 | 赛道定义、比较口径、份额/梯队及方法 | 选作研究渠道，尚无通用自动接入；原报告无法合法读取则保留缺口，不能用宣传转述代替 |
| 公司业务/主体 | 官网及投资者关系、巨潮资讯、上交所/深交所/港交所披露易；客户方公开案例或采购结果 | 实际主体、分部业务、经营规模、付费/交付事实 | 已有部分指定公司文档读取；没有全市场公司库。不能从集团数据套到子业务 |
| **岗位主来源** | **公司官网社会招聘及官网明确链接的ATS**：飞书、Moka、北森、Workday、Greenhouse、Lever等 | 岗位列表、完整JD、地点、职位与申请直链 | 仅少数适配器已实现；不是ATS名称列出就已接通。每个雇主租户单独核验 |
| 岗位与薪资补充 | **BOSS直聘、猎聘**；后备为智联、前程无忧、拉勾、LinkedIn Jobs | 平台岗位、薪资原文、招聘主体交叉核对 | BOSS/猎聘保持已有暂停边界；后备平台待逐个接入验收。不为获取薪资绕过验证码 |
| 招聘公告补充 | 公司认证招聘公众号、官方招聘活动公告 | 新岗位线索及公告原文 | 核账号归属、发布日期；海报/活动不等于完整JD或当前在招 |
| **全市场发现入口** | 当前可用的web搜索工具 | 两路入口发现；跨公司岗位名称词/正文职责词召回 | 可由代理有界调用；尚未成为CLI自动搜索调度器。底层搜索供应商未返回时不声称用了百度/Google等具体引擎 |

公司具体官网/ATS入口复用 `../config/company-discovery.json`；已实现适配器以 `../registry.mjs` 为准；政策域名复用 `../config/policy-sources.json`。本次不猜测新公司的招聘路径。行业报告和其他候选渠道的**具体原文/站点入口必须在运行前发现并核验后加入本轮清单**，未核不能自动导航。频道目录只定“查哪里、查什么”，不是运行时网络放行表。

### 每次扫描前的来源准入清单

先产出每条实际来源的 `source_id/channel_id、发布方或雇主、origin/entry_url、归属证据、A/B用途、标题/正文搜索能力、分页能力、读取方式、实现状态、访问状态、最后检查/成功时间、halt原因、证据引用、下一步`。

- 实现状态与访问状态分开。适配器实现了，不代表当前能访问；历史成功，不代表今天已验证；`company-discovery.status=verified`主要是归属证据，不是采集成功。
- 未核源只进准入待办；历史成功源先做本轮许可/robots/归属检查；当前受限源保持暂停；浏览器隔离按现有策略从严，不通过目录配置清除halt。没有本轮准入和真实原文回执，不能出“渠道已扫”结论。
- 公开且独立的官网来源可以单独核验，不将其内容冒充被限制平台的结果。来源受限不能换代理、浏览器、接口或搜索缓存来重取同一被限制内容；搜索摘要不升级为完整原文。
- 主动搜索和导航共享串行队列，间隔10–20秒，严格来源从严；验证码/401/403/429/访问拒绝首次即停，登录/付费由本人处理。普通技术根因最多三轮修复，失败留待办。
- 一个岗位多个来源保留关联与冲突：优先当前官方完整JD定义职责；薪资按发布方、时间、城市、职级分别留原文，只在确认同岗后关联，仍不自动认定固定底薪达标。不同来源有效时间冲突则进入待核。

## 三、执行链路的顺序与验收

**冻结方向和范围 → 来源准入 → 行业/公司候选底册（层级可待核） → A取得JD / B有界冷启动 → GPT-6实证提词 → B扩展及新公司回补 → 分层补证、去重和薪资核验 → 分批个人匹配 → 按行业/层级报告及覆盖审查。** 分类补证与采集可以交错，不把行业研究变成无限等待。

先读[实际源码盘点](source-runtime-audit-2026-09-11.md)，不要只依据规则配置判断能否运行。本次不声称已实现自动公司发现、分层、词库引擎、跨工具调度和分组UI。唯一实施清单仍为 `../progress.json`，遗留问题集中 `known-issues.md`。

下一轮最小验收：用一小波声明范围，证明新雇主能进入底册、陌生标题能从正文召回、两路同岗保留发现链、四类分层有据或明确待核、来源状态真实、固定薪未知不误报。预算用完可暂停续接，不把这一波当全市场完成。没有市场总分母，不给全市场覆盖百分比。

## 四、规则检核案例（虚构，不是公司结论）

1. 40人公司：全国细分软件份额在充分覆盖市场的独立报告中第2，且研究明确属于领先梯队，另有独立原始来源的商业交付证据；同口径和时效均核验后可为**行业大厂**，组织规模另列。只有名次则仍待核。
2. 万人集团：新AI业务只有集团品牌与总营收，**该AI赛道地位待核**，不继承集团名气。
3. 行业报告明确某公司为成熟挑战者，另有多客户连续交付证据，可为**行业中厂**；仅未进入前5不足以判中厂。
4. 外部比较及业务材料均说明仍在试点商业化，可为**行业小厂**；查不到任何材料则是**待核**。
5. 某公司在CRM有份额证据、AI Agent只发布概念，两条赛道分别判断，不能通用一个大厂标签。
6. 同一公司宣传稿被转发十次，只算一个原始来源；2023年排名未补新证据，不能作为2026年已核地位。
7. 同赛道前两家占95%，第5家仅0.3%且只有付费试点：前5不足以判头部。保留份额和试点证据，在梯队/阶段冲突未解时为**地位待核**；不得按名次覆盖有限市场地位的反证。
