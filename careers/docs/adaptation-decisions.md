# 为什么不是直接运行开源项目

本文件记录实际验证后的取舍，不将开源仓库能安装或离线测试通过等同于网站可用。

| 问题 | 本轮真实证据 | 已落地处理 |
| --- | --- | --- |
| 历史平台接口不保证当前可用 | MiniMax旧公共POST返回405；当前前端包含匿名会话/签名处理 | 不复制签名或CSRF逻辑；使用获批的普通公开浏览器页面，保留实际响应、DOM、原生链接和截图。旧接口失败记录不抹去、不自动重试 |
| 首页或招聘类别不等于完整JD | 智谱6类、月之暗面16张职业介绍卡；Moka入口发生同地址重定向 | 类别不进入岗位库；保留入口证据与受限原因 |
| 官方站点提供数据的方式不同 | 百炼：HTML与Nuxt字面量；DeepSeek：官网引用脚本中的公开数据与展示过滤；MiniMax：正常页面公开响应 | 独立适配器只处理经过核验的输入，统一规范化/存储/证据契约，不先建设十个未验证接口 |
| 全量、关键词和缺失详情不能混为完整扫描 | DeepSeek34条中1条只有占位文案；MiniMax默认第一页10/202，Business4/4、销售9/9 | 分别标partial、scope、查询页计数；48条完整JD不等于三家公司全量招聘。失败/不完整/查询截断不得推断关闭 |
| 通用求职机器人不了解个人事实边界 | 用户直接销售/团队管理、个人210家商户、AI工具自测与AI产品商业化之间有真实差值 | 事实与偏好分开，JD原句和个人事实原句映射；80分只是覆盖分，独立语义复核前为草稿，不自动投递 |
| 仓库默认运行时和本机不同 | 系统Node22，本机Codex附带Node24；现有Playwright与Chrome可用 | 选择性复用协议/结构思路，沿用Node24 ESM SQLite，不引入Bun、外部LLM API账单或新控制台 |

## 后续每轮的成本控制

1. 采集、解析、去重、变化检测、薪资分类和报告由程序完成，模型调用为0。
2. prepare先按规则召回，只给模型必要岗位字段与事实摘录，不携带原始HTML/重复source_record或完整聊天历史。
3. 内容、事实、偏好、规则与简历哈希未变化则复用分析；同一待分析批次再次prepare返回同一检查点。每轮最多20条。
4. 核心匹配和独立审核使用用户指定的GPT6max；快模型用于入口整理、明确的小任务及测试执行。实际agent ID和接受的模型参数有记录；工具未提供的token数量留空，不编造节省比例或账单。
5. 发布后日常更新不重新开展完整架构研究。仅新增来源、接口变化、已发现缺陷或重大事实变化触发相应模块检查。

源码引用与许可见 `careers/THIRD_PARTY.md`、`careers/providers/THIRD_PARTY_LICENSES.md`；原始开源审查材料保留在 `research/company-careers/`。
