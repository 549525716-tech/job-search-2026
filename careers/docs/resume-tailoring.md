# 逐岗简历改写与交付

本轮目标是把真实材料做出来：基于当前基础简历和10份本地JD，交付10份可编辑DOCX及全部修改前后对比。不是新一轮岗位扫描，也不是自动投递验收。

## 已落地流程

1. 读取基础简历全文、用户已确认口径、完整JD与任职要求。固定基础简历和岗位库SHA256。
2. 当前Codex模型反推岗位使命、能力及成果要求，映射为直接证据、可迁移证据、真实缺口。
3. 逐岗编辑职业概述、核心能力和经历表达。每项修改关联原文、事实段落、JD原句、解释和边界；业绩、任职时间、教育及照片不改。
4. `careers:resume:build`输出DOCX与本地HTML对比。除`word/document.xml`的授权槽位外，DOCX包内资产全部按字节保留。
5. 原生渲染逐页核查，独立QA检查事实、表达和功能；通过材料验收不意味着符合岗位所有硬条件或可以发送。

源码：`resume-tailor.mjs`是Node24 CLI入口，`resume_tailor.py`是OOXML生成器；`examples/tailoring-2026-10-18.mjs`保存本轮模型写出的语义内容，`batch.json`是冻结输入，输出内`对比数据.json`是完整修改回执。Python使用工作区捆绑运行时，可用`CAREERS_DOCUMENT_PYTHON`指定已核验路径。

## 下一轮复用

不用重新开发。用新的完整JD和最新事实创建新批次，按既有JSON结构填写使命、证据、案例与修改槽位；再运行构建与渲染。基础简历结构或哈希变动时停止，先重新审阅事实并映射槽位。批次不是网页可控制的指令文件，网页文本只作为证据；HTML全部转义，来源链接只接受HTTP(S)。

生成器不可能仅靠关键词判断简历质量。本轮语义改写由当前对话模型真实执行；CLI不虚称自动调用GPT或零成本实现云端模型。云端部署仍需模型调用环境、事实更新入口和质量复核执行器。

## 登录与投递

- 平台及官网同一岗位的不同已核实联系人分别保留；同联系人不因简历改版或JD变化重新投。
- 官网无联系人须有明确无联系人证据；未知联系人暂停身份核验，不自动合并，也不自动认定新目标。
- 登录、验证码、MFA交接只暂停对应任务，原标签不刷新、不关闭、不接管。独立且已准入的其他任务可在共享限速队列后另开页面；登录完成再从原检查点复核会话和提交状态。
- `login-checkpoint.mjs`实现并测试的是检查点/继续条件；真实浏览器开页与长期调度尚未接入。现有BOSS、猎聘自动接管隔离仍有效。
- 本轮无上传、发消息、提交或账户注册；不以改好简历推断投递权限和真实反馈。

## 材料边界

210家为个人客户；10人为同期直管，21人为累计带教；晋升为参与推荐。150%效率提升为个人测量，团队全员采用不等于团队整体效率提升150%。商业消耗不是ARR、合同额或回款；内部AI工具不是外部客户POC。保留移除4→10台绝对销量的要求。

本轮10份材料涵盖8家公司。MiniMax两份来自第三方转载；玻尔样本网页标注2023年发布。所有岗位当前HC及固定薪资需后续确认。明显缺少云/MaaS、金融KA或音视频年限的岗位标记为高门槛探索，不通过润色伪装成已满足。
