# 先宽度，后深度：业务交付门槛

依据：用户2026-09-16明确指出当前资料不达标，要求在交付前按其标准验收，先取得市场覆盖宽度，再做深度分析。本文件覆盖此前以可用雏形、少量样本或页面完成作为本阶段业务交付依据的做法；不改变访问安全、人工登录、投递和定时授权。

## 当前结论

当前报告是**宽度验收未通过的阶段样本**，不是正式猎头推荐结果。已有页面功能、原始证据与局部评分保留，技术验证不作废，但不能据此认定业务达标。状态唯一入口为 `careers/progress.json.business_acceptance`。

已知缺口的最新范围以 `careers/progress.json.business_acceptance` 及其指向的覆盖账本为准，不以本文件的历史批次数作为最新进展。已有公司名称不等于已逐公司完成多渠道检索；候选公司与来源的待扫、分页、正文和受限项必须分别核对；公司别名、海外线索不能用于抬高国内机会覆盖。不能计算未知分母的全市场覆盖率。

## 每轮最终目标（2026-09-23）

用户要求每次更新均以 **全市场已收齐** 为目标，追求大而全，而不是定量取样后收工。范围沿行业、公司、渠道、名称及正文关键词持续扩展；每波冻结范围便于核验，新发现转下一波续扫，不能因不在原种子清单内遗漏。

“目标”与“已经完成”必须分开：行业和市场本身会变化，没有可核验的全市场分母时，不能宣称穷尽互联网。即使本波全部任务完成，也只能证明本波的声明范围，不能自动提升业务验收。停止在真实受限或执行检查点时，保留下一波清单，不将停止改写为完成。

每轮汇报按以下顺序收尾：实际新增行业/公司/来源/岗位及其证据；复用与去重的依据；仍待扫、待翻页、待补正文和受限范围；下一波入口。不能取得的计数写未知，不能把计划任务当已执行。最后一行固定为：**目标：全市场已收齐**。

## 快速分流与重复略过

| 快速类别 | 执行动作 | 不得误判 |
| --- | --- | --- |
| 新增行业/公司/来源/关键词 | 优先拓宽，执行A/B交叉回补 | 未核名字只是线索，不是独立公司或已扫完 |
| 到期复查 | 下一次更新重新检查已知招聘列表，发现新增及变化 | 搜过的公司不能永久跳过；未复查不等于未变化 |
| 待翻页/补正文 | 从已存检查点继续，保留缺口 | 部分成功不等于完整，失败不是零岗位 |
| 内容变化 | 保存新版本，重新核对受影响字段及匹配 | 旧薪资、旧JD或旧评分不冒充当前结论 |
| 已核重复 | 同批相同任务复用成功原始回执；未变化分析复用缓存 | 只因标签、岗位名称或公司名称相同不能略过 |
| 受限待恢复 | 保留阻塞原因，继续其他独立已准入来源 | 不机械重试、不换接口绕过、不写成已完成 |

检索任务身份必须同时比较来源、行业/雇主范围、查询原文、全部筛选、地域、语言、页码/游标和规则版本。同批完全一致且有成功原始回执才复用，记录复用目标与两路发现证据；近义词先保留，不用语义相似度误删召回机会。成功的搜索回执仍只证明该查询执行过，不证明结果全文或公司岗位收齐。部分取得的页面可复用已有证据，但缺失部分保留待续，不把整个任务略过。

重复标签可去重展示；职位和联系人继续按 `careers/docs/open-discovery-and-identity.md` 关联。保留跨平台入口、不同已核HR、原生岗位ID和工作地点；未知身份保守保留。原始观察不删除。模型分析仅在JD、个人事实画像、规则版本和证据上下文均未变时复用，避免重复分析占用拓宽时间。

以上是执行和验收契约，未新增自动调度器或网页按钮。规则固化不是新扫描，也不解除现有来源隔离。

## 宽度阶段先做什么

1. **行业与需求覆盖。** 从现有8个研究方向起步：大模型开放平台、云与AI基础设施、数据/AI开发平台、企业软件与营销数字化、AI企业应用、汽车与智能出行、工业智能化、机器人与智能硬件。逐方向扩展细分场景；这是研究起点，不是行业白名单或已确认的市场结论。
2. **公司发现。** 使用来源不同的行业资料、公司披露、招聘资料与关键词命中扩展公司底册，记录来源、业务、官网及招聘入口。国内岗位优先，海外地点单列；不只查熟悉的大模型公司，不等分层、融资或身份全部补齐才保留线索。
3. **公司与岗位初扫。** 逐公司建立官网/ATS、招聘平台和其他公开来源任务。记录实际渠道、标题、城市、薪资原文、职位链接、读取日期和正文状态。最低限度检查内容，不只按熟悉标题召回；薪资未知、名称陌生、未评分不阻止入库。
4. **双路线交叉扩展。** A按行业找公司再找岗位；B按行业、职能名称、职责及业务场景词跨市场找岗位，再回补新公司。使用中文和适用的英文别名；新公司与新词必须有待续项，入队不等于已执行。
5. **先看覆盖，不抢做精修。** 可以顺手保存可取得的完整JD、保留原评分，但暂停少量岗位反复深评、定向简历精修和非必要UI开发。除用户单独选岗要求外，深度工作不能占用本阶段主要资源。

## 交付前必查

| 检查项 | 必须给出的证据 | 不通过的典型情况 |
| --- | --- | --- |
| 行业广度 | 版本化行业/细分方向清单及逐方向发现记录 | 只在少数熟悉行业取样，其他行业未执行或无法说明 |
| 公司广度 | 候选公司底册、发现出处、别名关系与实际初扫状态 | 把名称目录当已扫描公司，少量种子被当市场边界 |
| 渠道广度 | 每家公司各渠道的真实入口与结果、分页/待续/受限状态 | 只查一次搜索或某个易读ATS，就称已扫公司 |
| 岗位召回广度 | 销售/KA、商务渠道生态、市场、商业运营、销售管理及业务型售前的名称和内容查询记录 | 只检索AI销售或英文Account Executive，遗漏正文商业职责 |
| 双路线与续接 | A/B各自贡献、新公司回补与剩余待扫清单 | B检索结果没回到A，新发现一直只停留在队列 |
| 真实性与边界 | 原始证据、原生岗位/联系人、公司关系、重复规则和采集时间 | 观察数当独立岗位数，报告生成当新扫描，受限当零岗位 |

逐项出具“有证据 / 部分 / 未执行 / 受限”的判断，并说明不足是否影响用户按行业选择机会。存在未解决的关键覆盖缺口，业务验收仍不得通过；列出缺口本身不算解决。正式通过必须引用覆盖清单、来源凭据与验收结论，不能只改一个状态字段。

**不以凑满某个公司或岗位数作为充分条件。** 用户没有给出数量型达标阈值，不能将自定的100家或200家说成用户标准。超过100家时讨论大小厂分类是另一个待办，不是宽度通过条件。

## 暂停、进度与深度阶段

单批技术预算只决定检查点，不决定业务完成。预算用完、来源受限、限速记录异常或访问失败时保存证据和待续项，明确仍未达标，不隐去剩余任务，也不无限重试。暂停异常执行路径不等于扩大访问权限。

宽度证据经审查充分后，才把重点投入完整JD复核、结构化评分、个人案例转译和选岗材料。未经用户选岗授权，仍不投递。阶段样本可供查看，但不得作为达标结果交付；本规则更新本身也不代表新增了市场覆盖。
