# 来源级兜底

2026-09-22用户授权：内置招聘页白屏时，故障渠道停止自动接管，独立可用来源继续。目标是保存有效采集能力，不保证所有网站可采，也不声明白屏根因已修复。

## 执行顺序

1. 保留普通BOSS/猎聘标签和历史证据。账号、页面、详情读取、无人值守复用四种状态分开，不把about:blank直接判成登录失效。
2. 对出错源登记blocked/failed及原因，暂停该源；不重复getTab、不新建相同登录页、不刷新保活、不清Cookie、不自动切桌面。
3. 运行 `npm run careers:fallback -- --companies minimax,bailian-ai,deepseek`。显式范围内串行执行已验收固定适配器，隔离和旧halt保持有效，每源结束落盘；未知来源记录not_scanned。命令退出2表示有受限/部分结果，不代表已保存岗位丢失。
4. 公开网页扩展由本次Codex会话按A/B双路线执行，先冻结查询预算，再用web-session共享队列留证；不访问已经阻断的源，不用缓存页替代受限原文。Codex辅助研究不是已实现的无人值守CLI搜索。
5. 将新取得岗位及原文证据接入现有行业→公司→岗位报告。采集时间不等于发布日期，历史观察保留原时间；未公开薪资/地址/正文保留空值及原因。
6. 保留BOSS/猎聘完整JD、HR联系入口的待补清单。其他来源有同公司岗位，也不能将该待补项标为完成。

## 失败边界

- CAPTCHA、401/403/429、登录验证等访问限制：首次停止该源，不自动重试、不借兜底绕过。
- 单源解析或网络失败：保存失败证据，继续下一独立源。失败或分页不完整不能判空、不能推断岗位下架。
- 共享锁冲突、数据库/原文/报告/检查点持久化失败等全局基础设施问题：停止本批，剩余源保留pending（尚未扫描），记录停止原因；不能假装可以可靠继续。存储阶段统一标记 `COLLECTION_PERSISTENCE_FAILED`，不依赖有限系统错误码名单。
- 源只有搜索摘要：仅保存线索；只有公开页职责及要求可读并逐条留证才算取得JD。官方列表完整性与单个JD完整性分开。
- 桌面专用浏览器是后续候选方案，不是本轮实现，不访问用户日常Chrome。

## 验收与报告

每批交付run.json、summary.md、完整可取得的岗位及源证据、未扫/受限队列。源故障隔离、本地测试和真实采集分别给结论；不能用局部通过宣称全市场覆盖或BOSS/猎聘恢复。本批没有定时任务、投递、消息或简历上传。

首次实际验证见 `01_行情收集/official-careers/research/fallback-2026-09-22/report-run.json` 和 `live-verification.json`：5个公司来源共54条原文观察，20条已拆职责/要求、34条保留源全文未拆。16次已记录请求的最短间隔10.729秒；BOSS/猎聘页面请求0次。查看现有 `decision-review.html` 中的“最新采集批次”；默认商业主线筛选不代表删除其他原始记录。

后续每轮仍须冻结当轮来源与预算、留新回执，再更新报告输入；历史成功不能自动证明今天可用。进程中断后running/pending状态不是成功，必须核查检查点，不盲目重新执行整个批次。此命令尚未提供无人值守自动续跑。
