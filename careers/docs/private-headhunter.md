# 私人猎头：职业发展与投递闭环

## 当前入口（2026-10-18）

请先读 [持续私人猎头架构](autonomous-headhunter.md)。当前目标已扩展为持续发现 + 事实增量维护 + 高质量岗位专属简历 + 有效授权内的自动投递与反馈，不再仅限手工选岗的最终产品形态。长期策略授权、生成器、真实投递和云运行仍待实施/验收；最新规则覆盖下方旧固定薪门槛、角色偏好和实现状态。实际薪资/角色读 `preferences.json`，权限读 `application-policy.json`，进度读 `progress.json`。

## 历史设计（2026-09-10，非当前运行声明）

版本：2026-09-10。依据用户本轮直接要求更新；这是项目目标及执行契约，不是全功能验收声明。

## 一句话定位

理解贺文杰的过去与现在，持续发现未来可行的职业路径；从政策、产业、公司到岗位逐层验证，帮助本人选择，并执行被授权的材料准备与投递，通过真实招聘反馈修正判断。

核心目标不是抓最多JD或追逐最高薪资标题，而是获得有机会进入、能积累管理或长期To B能力、收入结构更可预期的面试及工作机会。项目是个人决策支持与执行系统，不代替本人决定人生方向，不承诺就业或收入稳定。

## 主漏斗

2026-09-11扫描入口更新：执行 [双路线岗位发现与扫描规则](dual-route-discovery.md)。原漏斗保留为主线A，增加关键词反向发现路线B：从真实JD提炼名称/内容词 → 市场岗位 → 新公司 → 回补A。公司池和词库滚动扩展，不以固定公司数或分析批次上限代表扫描完成。配置见 `../config/discovery-policy.json`；当前仅规则已定义，尚未实现自动扩展和调度引擎，本次没有启动扫描。

**个人职业目标与事实底座 → 国家政策/产业趋势 → 可验证的商业需求 → 行业头腰部公司 → 公司真实岗位 → 个人路径匹配 → 用户选岗授权 → 简历及申请材料 → 登录后填表、附件和提交 → 面试/拒绝/无反馈 → 调整方向与材料。**

政策只负责发现值得研究的方向，不直接证明订单、公司稳定或岗位适合。没有政策关键词命中的成熟To B公司也可通过补充发现路径进入，不能机械排除。

### 1. 政策与产业情报

按周检查新增、修订、到期、废止及重要执行进展。长期纲要作底座，每周重点读取变化，不每次重读全文。

优先国务院/中国政府网、发改委、工信部、科技部、国家数据局；再看地方实施文件。原文件、正式规划、实施办法、申报通知、征求意见稿、政策解读分别标注。国家级与地方级、全国适用与定向试点分别处理。每条至少保留发布主体、文号、成文/公开/生效/截止日期、适用对象、原文链接、观察时间和证据等级。

解释必须回答：支持什么活动、谁可能付费、落地到哪个业务环节、能否形成采购需求、有哪些执行条件和反证。财政投入、项目申报与公司营收不等同；过期申报不能当作正在兑现的利好。

已核验的示例底座为中央网信办官方转载的国务院《深入实施“人工智能+”行动的意见》，具体原文链接、响应和日期以 `careers/config/research-documents.json` 与研究回执为准。国家数据局入口访问受限，不标记为本轮已读取。发现范围不应局限于基础大模型公司，这是研究方向推论，不是该领域公司正在招聘的证明。

“十五五”纲要作为重点核验入口；本轮发现官方全文链接，但工具读取超时，尚不标记全文已核验，也不编造最新支持名单。[全国政协网站候选原文入口](https://www.cppcc.gov.cn/zxww/2026/03/16/ARTI1773644951646391.shtml)

### 2. 从产业到公司

每个重点赛道建立行业大厂、中厂、小厂及地位待核四类公司池，统一执行[行业分层与来源准入](industry-tiers-and-sources.md)。地位与组织人数分开，固定地域和时间口径，按独立市场比较与商业事实取证；无依据不默认小厂，不靠融资新闻、知名度或模型自报前十。四类均可进入岗位发现，分层研究不是采集阻塞点。

每家公司记录：主体及品牌关系、细分赛道、客户类型、产品与收费方式、已核验案例/收入证据、官网和招聘域名归属、经营风险、最近核验时间。区分集团与具体业务线、直营招聘与外包/代理、国内与海外主体。

不规定每个赛道必须凑十家，不让公司的名气替代个人机会判断。现有十家公司是首批种子池，不是永久白名单。

### 3. 从公司到岗位

优先公司官网/ATS，BOSS和猎聘作为补充发现、薪酬核验及投递渠道。不同来源同岗位关联但不合并掉冲突：ID、地区、业务线或薪资不同要分别留证。

保留JD全文、岗位和申请链接、公司、地区地点、薪资原文、底薪/浮动/OTE/年包区别、发布与观察时间、完整性、招聘有效性及采集证据。官方职位链接不等于仍开放，失败或部分采集不能推断下架。

### 4. 从岗位到个人路径

四个维度分开解释，不揉成“80%成功率”：

1. 胜任证据：直接证据、可迁移证据、真实缺口；学历、专业、年限、资源和技术门槛。
2. 长期价值：能否积累客户经营、行业方案、团队管理、运营机制或持续交付能力。
3. 收入与业务风险：固定/浮动收入、试用期差异、考核口径、独立获客压力、客户与收入集中度；未知不当作稳定。
4. 进入与发展路径：立即主攻、可接受的过渡、需补证的探索、暂不推荐；说明放弃了什么、换取什么。

建议研究的路径假设：
- 管理主线：销售管理、销售运营/商业运营管理、区域客户经营管理。核查真实团队规模、招聘绩效权限、预算和汇报关系；“经理”可能仍是个人贡献者。
- 长期To B主线：客户成功、战略客户经营、行业解决方案、生态伙伴经营及商业化运营。不因To B名称自动认定稳定。
- 行业迁移主线：汽车数字化、营销技术、AI企业应用等与既有场景相邻方向；逐条验证商业模式和JD，不预先宣称适配。
- 最新主攻范围：市场营销、销售及KA、商务渠道生态、销售及商业运营；产品经理明确排除。产品市场营销不等于产品经理，仍可研究，但品牌、英文和海外专项能力不能推定。
- 业务型售前和客户成功保留相邻机会；FDE/技术交付不默认推荐。若需要生产代码、系统集成、云交付和客户POC，必须单列硬缺口，不能用个人AI工具替代。

本人已于本轮明确：固定月薪至少人民币20K。明确披露为固定薪且范围下界达到20K才记作达标；15–30K或未说明底薪构成的20–30K不能直接通过，跨门槛区间、未披露、年包、外币和OTE分别待核验，不以行业平均数或年包折算补齐。达标表示来源披露，不保证最终offer；投递待遇未确认岗位须在所选批次中明确允许先沟通核薪。

## 用户控制点与自动投递

### 控制点

本人选择要投递的具体岗位，并发出本批“优化材料并投递”的授权。仅收藏/感兴趣/问匹配度不等于授权。一次批次授权可以覆盖已列明岗位的证据保真微调、申请表填写、指定附件上传、最终提交和已批准的首条招呼，不要求每页重复确认。

每次批次绑定公司、原生岗位ID、JD哈希、投递来源及实际接收方、个人事实版本和允许修改范围。授权可撤回。JD或接收方变化、出现新事实、新声明、未确认的薪资/到岗时间等重要回答，暂停该项请本人决定，不在后台猜答案。

### 系统负责

拆JD → 选择基础简历 → 证据保真微调 → 输出差异与缺口 → 生成岗位专用附件 → 映射表单字段 → 填写与上传 → 回读核对 → 检查批次授权 → 提交一次 → 回查确认页/申请记录 → 保存投递回执与版本。

证据保真的自动微调可调整定位、顺序、业务语言和已有成果表达；不得新增未确认经历、学历、技术能力、合同金额或项目结果。80分不是录用概率，沿用基础简历仍需完整JD、关键门槛、主线与独立复核通过。

申请表答案使用带来源的事实库；必填但未知的字段集中问一次。工作许可、法律声明、敏感自报问题、推荐人联系、竞业约束等不自动推断。可选隐私字段不主动填写；不假定用户愿意披露。

### 本人负责的常规介入

注册、登录、验证码、短信/邮箱验证、多因素认证和必要实名核验由本人完成。系统接续同一已授权会话，不索取或记录明文密码/验证码，不复制日常浏览器所有Cookie。

除登录注册外，缺失事实或重要承诺也可能需要本人介入；不能承诺所有网站零介入。付费、签约、接受offer、协商最终薪酬、辞职及向无关接收方发送材料不包含在投递授权中。

### 不同渠道

官网ATS按平台逐个接入并验收。BOSS/猎聘也不是“点了就算完成”：沟通、发送简历、邀请面试是不同状态，须分别读回可见结果。站点验证或风控立即暂停，不绕过限制，也不复用已隔离的浏览器适配器作为投递执行器。

上传只允许该岗位/ATS核验后的接收域及指定文件；不上传其他简历或整个目录。发送超时/提交结果未知先查记录，不能立即再点，防止重复申请。

## 看板与反馈契约

这是后续同一个个人看板的视图契约，不新建营销页或另外一套控制台：

| 视图 | 用户应看到的内容 |
| --- | --- |
| 职业方向 | 现在可证明什么、希望走向哪里、主攻与过渡/探索路径及取舍 |
| 政策与行业 | 每周变化、支持机制、商业需求假设、反证、原文与时间 |
| 公司池 | 头腰部依据、业务与客户、招聘入口、稳定性未知项 |
| 岗位机会 | 政策/行业/公司追溯链、JD、薪酬地区、个人匹配与管理职责证据 |
| 待投递 | 用户选中岗位、授权、简历差异、字段缺口、登录/执行状态 |
| 投递反馈 | 申请回执、简历版本、沟通/面试/拒绝/offer及下一动作 |

每条追溯链允许未知节点，不用虚构政策或公司研究补齐。现有报告包含岗位、公开薪资线索、有限政策公司漏斗及猎头综合研判。公开索引不是完整JD或当前在招证据，不能与历史官网JD混算覆盖率。

申请状态分开保存：发现、待评估、已选、已授权、准备材料、待本人登录/补事实、待提交、提交结果未知、已确认提交、面试邀约、拒绝、已撤回。点击提交/打开入口不能写“已投递”。

评估最终使用经证实的投递数、面试邀约数、推进阶段和offer质量，而非网页打开数。按岗位方向、公司阶段、城市和简历版本记录分母与观察窗口；无回复标未决，不自动当拒绝。小样本先描述，不把一次拒绝归因于简历，也不为了提高回复率牺牲管理/长期To B目标。

## 运行与分工

角色定义和执行配置以 `careers/docs/headhunter-team.md`、`careers/config/agent-team.json` 为准。独立结果落在 `careers/agent-outputs/`，总控处理分歧后输出 `reports/headhunter.md`。当前输出须通过实际派发ID、输入哈希及原文引用校验；配置了角色不等于该角色已运行。

政策周报的期望频率为每周；本轮只定义机制，具体时间与定时触发未启用。高优先公司岗位做增量检查；遇到新/变更候选每轮最多20条个人分析。低变化内容复用证据，不重复展开全市场研究。

固定采集/去重/解析不调用模型。政策条款归纳、格式和确定性测试用gpt-5.6-luna/medium；方向判断、重点JD、材料边界和独立检核用gpt-6-astra/max。一个总控清单，按当轮需要拆任务，不为每个概念永久启动一个代理。

## 落地顺序与本轮边界

1. 本轮完成定位、策略配置、规则及授权契约调整，把新方向放入下一轮匹配输入；现有原始岗位与历史评估保留。
2. 先做一周政策到一个赛道、若干公司和真实JD的可回查样本，验证整条漏斗，而不是先追求覆盖所有产业。
3. 本人选一个岗位，完成一套可信材料和字段映射，再在该ATS上验收登录后填表/附件/提交/回查。未验收的ATS只输出材料和待办，不声称自动投递可用。
4. 扩展已验证的投递渠道与反馈记录，再确认政策周报和增量发现的运行时间。每个根因最多三轮修复验证，仍失败则隔离列问题。

当前自动投递执行器、注册登录接续、完整政策周报和反馈学习均未验收。所有外发运行开关仍关闭：这是实现状态，不再是永久禁止做私人猎头投递功能。
